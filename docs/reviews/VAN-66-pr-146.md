## Review fixes

- All Home copy, error messages and shift labels use Portuguese/English ARBs and AppLocalizations. Domain and Cubit return typed messages instead of Portuguese strings.
- Unknown family app membership is represented as null and the counter is omitted. Known membership includes 100% (D12).
- Unsupported stop confirmation no longer sends an HTTP request. A TODO(VAN-66) records the missing endpoint and next-stop/contact data.
- Route start requires a valid shift cached for the returned trip token. It never assumes MORNING when that shift cannot be resolved.
- The unused finish endpoint was removed.
- Rejected registration uses the shared card structure with error colors. Main-card buttons use the core UI components.
- Acceptance tests exercise all nine states, fixed shortcuts, outside-hours advisory and active-trip operations during a block.

## Verified backend contract

Checked against the sibling vanep-api-java source:

- DriverTripController exposes GET `/api/drivers/me/trips/today`, POST `/start` and POST `/finish`.
- TripStartRequestDTO requires a shift enum.
- TripResponseDTO has no next stop or contact information.
- ClientDriverResponseDTO identifies client-driver relationships, not transported children or family app membership.

Stop confirmation, real next-stop/contact mapping, a driver-students count and family app membership remain backend dependencies. No successful confirmation or invented family count is simulated in production.
